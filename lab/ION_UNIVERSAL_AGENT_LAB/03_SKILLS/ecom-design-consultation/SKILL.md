# ecom-design-consultation

Purpose: create professional alternative UI architectures from the existing ECOM OS canon without changing business semantics.

## Workflow
1. Load workflow map and screen contracts.
2. Inventory operator decisions, automatic work, repeated actions and dead space.
3. Produce 3 candidates: conservative, balanced, ambitious.
4. Each candidate must preserve owner boundaries, Product Vault context, approval gates and marketplace semantics.
5. Score each candidate: clarity, clicks, density, error prevention, responsiveness, learnability, continuity.
6. Reject any candidate that hides required state or creates duplicate owners/actions.
7. Output candidate specifications only to LAB UI candidate area.
8. No production writes.
